1. 기술 스택
===========================================================================

  프레임워크 : 전자정부프레임워크 3.8 (eGovFramework)
  언어       : Java 1.8
  DB         : MySQL 8.0  (스키마: winitest)
  WAS        : Tomcat 8.5
  ORM        : MyBatis (XML Mapper 방식, VO 없이 Map<String,Object> 사용)
  View       : JSP + JSTL + Apache Tiles 3
  CSS/JS     : Bootstrap 5.3.8 (CDN)
  트랜잭션   : Spring @Transactional + DataSourceTransactionManager
  페이징     : 전자정부 PaginationInfo + 커스텀 CustomPaginationRenderer
  로그       : log4jdbc (SQL 파라미터 포함 로깅)

  [중요 제약]
  - 모든 컨트롤러 엔드포인트는 POST 전용 (@RequestMapping method=POST)
  - GET 으로는 어떤 화면도 접근 불가 (login.do 만 GET+POST 병행)
  - java/egovframework 하위 파일은 직접 요청 없이 수정 금지
    예외: egovframework/com/cmm/CustomPaginationRenderer.java (직접 수정 허용)

4. 레이어 구조 (Controller → Service → DAO → Mapper)
===========================================================================

  Controller  (@Controller, @RequestMapping)
      ↓  @Resource 주입
  Service     (interface BoardService / UserService)
      ↓  @Resource 주입
  ServiceImpl (@Service, extends EgovAbstractServiceImpl)
      ↓  @Resource 주입
  DAO         (@Repository, extends EgovComAbstractDAO)
      ↓  selectOne / selectList / insert / update / delete 호출
  Mapper XML  (namespace="boardDAO" / "userDAO")

  [Bean 이름 규칙]
  - @Service("boardDAOService")  → @Resource(name="boardDAOService")
  - @Repository("boardDAO")      → @Resource(name="boardDAO")
  - @Service("userDAOService")   → @Resource(name="userDAOService")

  [DAO 상속 메서드]
  EgovComAbstractDAO 제공:
    selectOne(sqlId, param)     → Object
    selectList(sqlId, param)    → List<?>
    insert(sqlId, param)        → int
    update(sqlId, param)        → int
    delete(sqlId, param)        → int
  모든 호출 형식: "namespace.queryId" ex) "boardDAO.selectBoardList"

  [Map 기반 처리]
  VO 클래스 없음. 파라미터/결과 모두 Map<String, Object> 사용.
  DB 컬럼명은 SQL AS 절로 camelCase 변환:
    board_no → boardNo, re_lev → reLev, writer_pw → writerPw 등

6. 화면 이동 패턴 (POST 전용 아키텍처)
===========================================================================

  이 프로젝트는 모든 컨트롤러가 POST 전용이므로
  <a href="..."> 방식의 GET 이동을 사용할 수 없다.
  이동 방식이 두 가지로 나뉜다:

  ─────────────────────────────────────────────────────────────────
  [A] goPost() - 클라이언트 JS 에서 POST 이동 (버튼 클릭용)
  ─────────────────────────────────────────────────────────────────
  위치: header.jsp 의 <script> 블록 (전 페이지에서 사용 가능)

  동작: __navForm (숨겨진 form) 에 action 과 파라미터를 동적으로 세팅 후 submit
  용도: 단순 화면 이동 (글쓰기 버튼, 목록 버튼, 상세 페이지 클릭 등)
  제약: enctype 이 기본(application/x-www-form-urlencoded) 이므로
        파일 업로드가 필요한 write/edit/reply 폼에는 사용 불가

  사용 예:
    goPost('board/write.do')
    goPost('board/detail.do', {boardNo: '5', currentPageNo: '2'})

  ─────────────────────────────────────────────────────────────────
  [B] bridge.jsp - 서버 처리 후 POST 이동 (컨트롤러에서 사용)
  ─────────────────────────────────────────────────────────────────
  위치: /WEB-INF/views/bridge.jsp

  동작: 컨트롤러가 param 맵에 bridgeUrl 을 담아 "bridge" 뷰로 포워드 →
        bridge.jsp 가 즉시 form 을 만들어 bridgeUrl 로 POST submit
  용도: 글 등록→목록, 글 수정→상세, 로그인→목록 등 서버 처리 완료 후 이동
  주의: ${param} 은 HttpServletRequest 파라미터를 의미하므로,
        컨트롤러가 model.addAttribute("param", map) 으로 넣은 값은
        반드시 ${requestScope.param} 으로 접근해야 함

  컨트롤러 사용 패턴:
    param.put("bridgeUrl", "board/list.do");
    model.addAttribute("param", param);
    return "bridge";

  ─────────────────────────────────────────────────────────────────
  [C] 각 JSP 전용 form - 파일 업로드 페이지
  ─────────────────────────────────────────────────────────────────
  write.jsp, edit.jsp, reply.jsp 는 파일 업로드(enctype="multipart/form-data")가
  필요하므로 __navForm 사용 불가. 각 JSP 가 자체 form 을 보유.
  detail.jsp 도 boardNo + writerPw + 검색조건을 한 번에 전달해야 하므로 전용 form 사용.

7. 게시판 컨트롤러 엔드포인트 목록 (BoardController)
===========================================================================

  URL                         메서드  설명
  ─────────────────────────────────────────────────────────────────────────
  /board/list.do              POST    게시글 목록 조회 (페이징 + 검색)
  /board/detail.do            POST    게시글 상세 조회
  /board/updateHitAjax.do     POST    조회수 증가 Ajax (숫자 반환 @ResponseBody)
  /board/write.do             POST    게시글 작성 폼
  /board/writeProc.do         POST    게시글 등록 처리
  /board/edit.do              POST    게시글 수정 폼 (비밀번호 확인 포함)
  /board/editProc.do          POST    게시글 수정 처리
  /board/delete.do            POST    게시글 삭제 처리 (비밀번호 확인 포함)
  /board/reply.do             POST    답변 등록 폼 (5개 제한 체크)
  /board/replyProc.do         POST    답변 등록 처리
  /board/download.do          POST    첨부파일 다운로드 (스트리밍)
  /board/deleteFile.do        GET     첨부파일 단건 삭제 Ajax (JSON 반환)

  [주요 처리 흐름]
  writeProc: 세션 userNo 추가 → ref=0, reLev=0, reSeq=0 세팅 →
             insertBoard (useGeneratedKeys로 boardNo 자동 세팅) →
             updateRef (boardNo = ref 자기참조) → saveFiles → bridge→list

  editProc:  updateBoard → saveFiles → bridge→detail

  delete:    selectBoardDetail → 비밀번호 확인 → deleteBoard(계층삭제) →
             _deleteFileList 로 물리 파일 삭제 → bridge→list

  replyProc: countChildReply(parentNo 기준) >= 5 이면 차단 →
             insertReply (updateReSeq + insertBoard) → saveFiles → bridge→list

11. 계층형 게시판 구조 (답글 로직)
===========================================================================

  [컬럼 역할]
  ref     : 같은 스레드(원글+답글 묶음) 식별자. 원글의 board_no 값.
  re_lev  : 깊이. 원글=0, 답글=1, 답답글=2. 최대 2레벨까지만 허용.
  re_seq  : ref 그룹 내 정렬 순서. 답글 등록 시 부모 seq 초과 항목들 +1.
  parent_no: 직접 부모 board_no. 원글=NULL. CASCADE DELETE 설정됨.

  [목록 정렬]
  ORDER BY ref DESC, re_seq ASC
  → 최신 스레드가 위로, 같은 스레드 내에서는 계층 순서 유지

  [목록 들여쓰기]
  re_lev 값을 CSS 클래스로 활용: re-lev0(원글), re-lev1(답글), re-lev2(답답글)
  header.jsp CSS: .re-lev1 { padding-left: 20px; } .re-lev2 { padding-left: 40px; }

  [답글 등록 처리 - BoardDAOServiceImpl.insertReply]
  1. updateReSeq: 같은 ref 내 부모 re_seq 초과 항목 re_seq + 1 (자리 만들기)
  2. 새 답글 데이터 세팅: reLev=부모+1, reSeq=부모+1, ref=부모와 동일
  3. parentNo (String) → Integer 변환 후 insertBoard 호출

  [답글 개수 제한 (5개)]
  - 체크 기준: parent_no = 특정 boardNo (직접 자식만 카운트)
  - 원글(a1)에 5개, a1의 자식(a1-1)에도 독립적으로 5개 가능
  - 클라이언트: detail.jsp 에서 ${replyCount >= 5} 로 버튼/메시지 분기
  - 서버(reply.do):    replyView 에서 countChildReply >= 5 → bridge→detail
  - 서버(replyProc.do): parentNo 기준 재확인 후 >= 5 이면 차단

  [깊이 제한 (2레벨)]
  - 클라이언트: detail.jsp 에서 ${board.reLev >= 2} 로 메시지 표시
  - 서버 측 검증: 현재 미구현 (유효성체크_TODO.txt 참조)

  [계층 삭제 처리 - BoardDAOServiceImpl.deleteBoard]
  board 테이블에 parent_no CASCADE DELETE 가 걸려 있으므로
  DB 단에서 자동 삭제되지만, 물리 파일을 먼저 수집해야 하므로
  2단계(자식+손자)를 Java 코드에서 직접 조회 → 파일 경로 수집 →
  DB 파일 삭제 → DB 게시글 삭제 순서로 처리

15. 주요 주의사항 및 기억해야 할 포인트
===========================================================================

  1. 모든 이동은 POST. <a href> 나 redirect: 사용 금지.
     → 이동 필요 시 goPost() 또는 bridge.jsp 사용.

  2. ${param} vs ${requestScope.param}
     → ${param} 은 JSP HttpServletRequest 파라미터(쿼리스트링)
     → 컨트롤러가 model.addAttribute("param", map) 으로 넣은 값은
        bridge.jsp 에서 반드시 ${requestScope.param} 으로 접근

  3. 파일 업로드 폼은 반드시 enctype="multipart/form-data"
     → __navForm (goPost) 는 urlencoded라 파일 업로드 불가
     → write/edit/reply 는 전용 form 사용

  4. JSTL 에서 null 비교 주의
     → ${replyCount >= 5} 에서 replyCount 가 null 이면 0 으로 평가 → false
     → editView 비밀번호 오류 분기 시 반드시 replyCount model 에 추가 필요

  5. useGeneratedKeys 로 boardNo 자동 세팅
     → insertBoard 후 param.get("boardNo") 로 바로 사용 가능
     → saveFiles(request, param.get("boardNo")) 가 이 순서에 의존

  6. 계층 삭제 시 물리 파일 삭제 순서
     → DB 삭제 전에 selectFileListByIds 로 경로 수집 필수
     → deleteBoard 가 param 에 "_deleteFileList" 세팅 → 컨트롤러에서 파일 삭제

  7. 답글 replyProc 에서 parentNo vs boardNo 구분
     → HTTP 파라미터로 parentNo 로 넘어옴
     → countChildReply 체크 시 replyCheckParam.put("boardNo", param.get("parentNo"))

  8. searchType 와 searchKeyword 는 모든 이동에 같이 전달해야 함
     → 목록 검색 중 상세 조회 후 돌아왔을 때 검색 결과 유지를 위해
     → detail/edit/reply 의 form hidden 에 searchType, searchKeyword 포함

  9. CustomPaginationRenderer Bean 등록
     → context-common.xml 에 <bean id="customRenderer" class="...CustomPaginationRenderer"/> 필요
     → tiles type="customRenderer" 와 Bean id 가 일치해야 함

  10. bridge.jsp 는 Tiles 레이아웃 밖에서 동작
      → 컨트롤러에서 return "bridge" 시 Tiles 거치지 않음
      → bridge.jsp 가 <base href> 와 자체 form 을 가짐
