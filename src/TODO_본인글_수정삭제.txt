STEP 1. BoardMapper.xml 수정 (필수 - userNo 를 쿼리 결과에 추가)
===========================================================================

  파일: src/main/resources/mapper/BoardMapper.xml
  쿼리: getBoardDetail (id="getBoardDetail")

  현재:
    SELECT b.board_no AS boardNo
         , b.title    AS title
         ...
         , b.parent_no AS parentNo
         , DATE_FORMAT(b.reg_date, '%Y-%m-%d') AS regDate
         , b.modi_date AS modiDate
    FROM board b JOIN users u ON b.user_no = u.user_no
    WHERE b.board_no = #{boardNo}

  변경: modiDate 아래에 한 줄 추가
         , b.user_no AS userNo   ← 추가

  이유: JSP 에서 ${board.userNo} 와 ${sessionScope.loginUser.userNo} 를
        비교하려면 board 맵에 userNo 가 있어야 한다.
        userNo 가 없으면 JSTL 비교가 항상 false 가 되어 조건이 동작 안 함.

  [2-1] JSTL 비교 변수 선언 (버튼 영역 위)

    주의: JSTL == 는 타입 변환 없이 비교한다.
          sessionScope.loginUser.userNo 는 Integer (DB에서 int 로 옴),
          board.userNo 는 Integer (MyBatis int 컬럼 → Integer).
          둘 다 Integer 이면 == 로 정상 비교된다.
          만약 한쪽이 String 이면 false 가 되므로,
          문제 발생 시 fn:equals(String.valueOf(a), String.valueOf(b)) 방식으로 변경.

주의사항
===========================================================================

  1. userNo 타입 불일치 주의
     MyBatis 는 DB int 컬럼을 Java Integer 로 매핑한다.
     session 의 loginUser.userNo 도 Integer.
     JSTL == 로 Integer == Integer 비교는 작동하지만,
     Java 코드에서 String.valueOf() 로 변환 후 equals() 비교가 가장 안전하다.

  2. editView 에 HttpSession 파라미터 추가
     현재 editView 시그니처에 HttpSession 이 없으므로 반드시 추가해야 한다.

  3. 게시글 비밀번호(writerPw)는 삭제하지 않는다
     본인 글이면 비밀번호 체크를 건너뛰는 것이지,
     writerPw 컬럼을 제거하거나 NULL 로 바꾸지 않는다.
     남의 글 수정/삭제 시 여전히 writerPw 가 필요하다.

  4. 답변글 수정/삭제도 동일하게 적용된다
     답변글도 user_no 를 가지므로 같은 로직이 그대로 동작한다.
