1. 어드민이 아닐때 메뉴 프로그램 진입 시의 버튼은 권한이 있어서 제대로 등록,수정 버튼이 disabled 되는데 이후에 다른 페이지 갔을때는 프로그램 url이 없어서 그 전체 메뉴에 대한 권한이 있는데 버튼이 disabled 된다. 
ex) 설문관리 페이지 진입시에는 수정, 등록 버튼이 disabled 처리가 권한에 따라 잘 처리되지만 등록버튼 혹은 수정 버튼을 클릭해서 form에 들어갔을때는 프로그램 url이 없어서 권한 데이터가 없고 그래서 버튼들이 질문추가, 수정, 삭제, 저장 버튼들이 다 disabled 처리가 된다.  => 메뉴 들어갔을때 처음 나오는 페이지 버튼만 클래스를 넣던가 다른 폼에 진입했을때 권한 처리를 생각하든가 둘 중 하나를 고려해야할거같음.
=> 그냥 메뉴 들어간 페이지에서만 disabled 처리하고 등록 버튼을 눌러서 폼에 드간거는 이미 권한이 있는거니까 form에서는 클래스를 빼면 된다.그러면 지금 프로젝트에서 문제 없이 작동할거같다.

2. 설문 등록폼에서 저장/수정을 같이 쓰고 있는데 이때 원래 있던 데이터를 렌더링 할때의 문제점. jstl로 하진 않는데 <c>태크를 이용해서 스크립트 단에서 처리 중이다.

3. 메뉴 렌더링이 현재 권한에 따라 렌더링 되는게 아직 제대로 적용되지 않았다. 원래 메뉴는 그냥 가져오고 jstl단에서 c태크로 권한비교를 하고 보여주거나 말거나 했었는데 sql에서 처음부터 필터링해서 가져오는 방식으로 변경 => 모든 컨트롤러에서 메뉴를 호출했었는데 이 부분도 전체적으로 다 변경하거나 ajax방식을 이용해서 렌더링 하는 방법 중 택 1해야할거같다.

5. 서비스에서 DB의 UPDATE, INSERT, DELETE등의 작업이 여러번 일어나는 하나의 서비스에서 트랜잭션 적용하는데 INSERT,UPDATE,DELETE는 행수를 반환한다. 이때 반환된 행수가 > 0 클때만 원하는 작업이 성공한거니까 그런 판단문을 서비스에서 넣어야한다. EX) 롤 서비스 insertRole 메서드는 순서 UPDATE, 롤 INSERT, INSERT 된 롤 UPDATE, 메뉴권한 기본 데이터 INSERT가 타입이 안맞거나 서버 자체가 꺼지거나 이런 경우에는 롤백이 되지만 실제로 원하는건 생각한 데이터가 안들어갔을때가 롤백이 되어야한다.실제로 롤을 INSERT했는데 0건이 등록됐다거나 순서변경이 안됐거나 순서대로 실행하는 쿼리문이 생각한 방향으로 안됐을때 아래의 쿼리를 실행하면 안되고 롤백시켜야한다.

6. 롤컨트롤러의 roleSave에서 업데이트 서비스를 호출하고 cnt>0을 하는데 이것도 컨트롤러에서 할게 아니라 서비스에서 전부 계산을 하고 원하는 데이터가 들어가지 않았을때(실제 자바에러는 아님) 그때가 바로 cnt > 0 아닌 경우이다. 이때 서비스에서 롤백을 시켜야하는데 지금 그것도 실행이 안된다.

7. 롤 삭제 컨트롤러에서 수를 체크하고 서비스에서 삭제를 하는데 컨트롤러가 비즈니스 로직을 소유하고 있다.
